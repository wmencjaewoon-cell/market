# AS AI 사전 분석

## 구현 범위

- AS 문의는 `증상 작성 → 질문하기 → AI 답변 → 문의하기 → 이름/전화번호/가게 선택 → 견적 및 상담 요청하기` 순서다. 상담 요청을 최종 제출하기 전에는 가게/관리자에게 문의나 알림을 보내지 않는다.
- `AI 답변 없이 바로 상담`을 체크하면 `상담 정보 입력하기`로 바로 넘어간다. AI 동의, 호출, 분석 할당량 소모 없이 기존 문의를 접수한다. AI 서버 실패 시에도 바로 상담으로 전환할 수 있다.
- 사진/동영상은 **선택 사항**이며 증상 선택 또는 설명만으로 질문할 수 있다. 첨부 없는 분석은 예상 원인/추가 확인 위주로 답변하고, 시각적 관찰이나 셀프 수리 절차는 제공하지 않는다.
- 답변/상담 단계에서 이전 단계로 돌아가면 입력을 유지한다. 질문을 변경하면 이전 답변 연결이 무효화된다. AI 생략을 선택한 상담에는 과거 답변을 첨부하지 않는다.
- 사진/영상 합계 최대 5개, 사진당 10MB, 영상 1개/30MB/30초. 촬영 UI는 기존 10초 촬영을 유지한다.
- Gemini Files API로 실제 사진과 동영상 원본을 전송한다. 썸네일 한 장을 영상 분석으로 표시하지 않는다.
- 결과: 저위험 셀프 작업 / 복잡한 작업 / 전문가 필요 / 추가 확인 / 긴급 위험.
- 전기, 가스, 누전, 벽 내부 배관, 구조 균열, 천장/대형 누수, 보일러/난방은 셀프 절차를 제공하지 않는다.
- 위험 증상이 텍스트나 선택 항목에 있으면 앱에서 즉시 안전 안내를 표시한다. 서버에서도 독립적으로 재검사한다.
- 영상/이미지 속 위험도 모델이 분류하고, 서버 정책이 우선 적용된다. 키워드와 모델이 모든 위험을 발견한다는 보장은 없다.
- 원인과 관찰 내용은 AI 추정이다. 모델 출력 JSON을 검증하며, 수리 절차/공구/영상 링크는 모델이 생성한 값을 사용하지 않는다.
- 셀프 수리 절차는 `as_repair_guides`의 게시/검수 완료 가이드만 사용한다. 초기에 등록한 두 작업(가벼운 가구 보호 패드, 일반 수납장 손잡이)은 **내용 없는 미게시 초안**이다. 전문가가 절차를 작성/검토한 뒤 관리자 화면에서 게시해야 한다.
- 가이드가 철회/변경되면 과거 분석 화면에서도 이전 절차가 표시되지 않는다. 지원 작업의 추가는 금지 분야 검토 후 DB/공유 계약의 allowlist를 함께 수정한다.
- 자체 진단 정확도를 측정한 상태는 아니다. 공개 전 실제 사례와 전문가 판정으로 별도 검증해야 한다.

## 데이터 및 기존 문의 연결

1. 분석 초안(`as_ai_analyses`)과 불변 첨부 목록(`as_ai_media`)을 서버가 생성한다.
2. 로그인한 작성자가 미리 예약된 경로에만 업로드한다. 임의 경로/외부 URL을 서버로 받지 않는다.
3. 분석은 실제 문의를 생성하지 않고, 알림/채팅방도 만들지 않는다.
4. 사용자가 상담 요청을 제출할 때만 `estimate_requests.ai_analysis_id`를 연결한다. DB 트리거가 본인의 완료된 결과인지 검증하고, 한 분석을 여러 문의에 중복 연결하지 못하게 한다.
5. 사진/증상/분야를 수정하면 결과 연결을 무효화한다. 사용자 증상과 AI 추정을 하나의 본문으로 섞지 않는다.
6. 문의 제출 사진은 **기존 estimate-images 업로드 방식**을 그대로 사용한다. 비공개 분석 원본을 기존 공개 URL로 바꾸지 않는다. 문의 제출 시 원본이 기존 문의 첨부로 한 번 더 업로드되므로 잠시 중복 보관된다.
7. 분석 원본은 비공개이고 작성자만 읽는다. 제출 결과는 기존 문의 SELECT RLS가 허용하는 사용자에게만 보인다. 배포 DB의 기존 문의 RLS가 과도하게 열려 있지 않은지도 별도 감사해야 한다.

## 필수 배포 순서

### 1. AI 공급자 / 개인정보 조건 확인

현재 어댑터는 Google Gemini API이다. 2026-09-30에 배포 프로젝트의 키와 `gemini-3.8-flash`로 개인정보 없는 고정 텍스트를 분석해 실제 응답/JSON/안전 정책 검증까지 통과했다. 앱 전체 문의 저장이나 사진/영상 분석을 실제 검증한 것은 아니다. 무료 등급의 초기 테스트에는 개인정보·민감정보·기밀정보가 없는 샘플만 사용한다.

- 실제 고객 사진/영상은 개인정보가 포함될 수 있으므로 **활성 결제 계정이 연결된 API 프로젝트**로 운영한다. 무료 API의 데이터 이용 조건과 다르다. `store=false`는 대화 상태 저장을 끄는 옵션이지 전체 데이터 처리/보관이 없다는 보장이 아니다.
- Gemini 이용 조건에는 연령/대상 서비스 제한이 있다. 미성년자가 이용할 수 있는 앱에 그대로 활성화해도 된다고 가정하지 말고, 이 앱에 맞는 공급자 계약/접근 정책을 먼저 확인한다. 조건에 맞지 않으면 이 어댑터를 해당 서비스에 허용되는 공급자로 교체한 후 활성화한다.
- 외부 제공사 처리, 영상 속 음성/얼굴/주소, 국외 처리 및 보관에 대한 고지/동의/개인정보처리방침과 스토어 데이터 공개 항목을 운영 조건에 맞게 검토한다. 화면의 전송 동의만으로 모든 법적 요건이 충족됐다고 보장하지 않는다.
- 가이드와 위험 안내는 실제 전문가 검토가 필요하다. 특히 잘못된 '셀프 가능' 판정을 포함해 평가용 사례를 준비한다.

일반 사용자 공개 전 이 조건을 확인한다. 관리자 샘플 테스트는 아래 정리 작업을 구성한 뒤 `AS_AI_ACCESS_MODE=admin`으로 제한하고 `AS_AI_ENABLED=true`로 시작한다. 관리자 테스트 허용은 실제 고객 자료를 전송해도 된다는 의미가 아니다.

### 2. SQL 적용

Supabase SQL Editor에서 다음 파일을 순서대로 실행한다.

1. `supabase/migrations/20260928000000_as_ai_analysis.sql`
2. `supabase/migrations/20260929000000_as_ai_text_questions.sql`
3. `supabase/migrations/20260930000000_as_ai_completed_quota.sql`

1~2번을 이미 실행했다면 **3번만 추가 실행**한다. 2번은 첨부 없는 질문을 허용한다. 3번은 성공한 답변 기준으로 횟수를 계산하고, 결과 저장 RPC를 추가한다. **3번 SQL 적용 후** `analyze-as-issue` 함수를 재배포한다. 이전 SQL을 나중에 다시 실행하면 횟수 제한 함수가 예전 방식으로 돌아가므로 3번을 마지막에 적용한다.

실패 기록을 삭제하거나 횟수를 수동 초기화할 필요는 없다. 3번 적용 후 기존 실패 기록은 일일 횟수 집계에서 자동으로 제외된다. 기존 성공 기록은 유지하며, `completed_at`이 없는 과거 성공 건만 `created_at`으로 보완한다.

기존 프로젝트의 `profiles`, `estimate_requests`, `storage`를 전제로 하는 추가 마이그레이션이다. 기존 구독/채팅/지도 테이블을 바꾸지 않는다. 재실행 테스트를 포함한다. 운영 DB의 다른 수동 변경까지 검증한 것은 아니다.

### 3. 서버 비밀값 설정

Supabase Dashboard > Edge Functions > Secrets에서 입력한다. 앱 `.env`의 `EXPO_PUBLIC_` 변수에 넣지 않는다.

| 이름 | 값 |
| --- | --- |
| `GEMINI_API_KEY` | 발급한 서버용 API 키 |
| `AS_AI_MODEL` | 프로젝트에서 이용 가능한 영상/구조화 응답 지원 모델 ID. 현재 문서 예시는 `gemini-3.8-flash`; 실제 계정에서 확인한다. |
| `AS_AI_ENABLED` | 초기에는 `false`, 검증 및 아래 정리 작업 구성 후 `true` |
| `AS_AI_ACCESS_MODE` | `admin`: 관리자 테스트만 허용. 공개 검토 후에만 `public`. 값이 없거나 잘못된 경우에도 관리자만 허용한다. |
| `AS_AI_CLEANUP_SECRET` | 32자 이상 무작위 비밀값. Vault에도 동일한 값을 등록한다. |

계정당 최근 24시간 **정상 저장된 답변 5개**로 제한한다. `status = completed`와 `completed_at`으로 계산하므로 업로드 대기, 429/503, 시간 초과, JSON 검증 실패는 일일 횟수에 포함되지 않는다. 결과가 서버에 저장됐지만 앱으로 전달되는 중 연결이 끊긴 경우에는 이미 1회 사용한 상태이며, 같은 ID의 결과 확인으로 추가 차감 없이 복구한다. 실제 화면 표시 여부를 클라이언트가 신고하게 하면 한도를 우회할 수 있으므로 저장 성공이 차감 기준이다.

준비/실행/완료 RPC는 같은 계정 잠금 아래 동작한다. 실행 직전과 완료 시에도 성공 건수를 재확인하며, 오래된 작업의 실행권을 취소해 늦게 도착한 응답이 중복 저장되지 않도록 한다. 완료된 ID 재요청은 같은 결과와 완료 시각을 반환한다. `complete_as_ai_analysis`는 `service_role`만 호출할 수 있고 앱이 직접 결과나 횟수를 바꿀 수 없다.

실패 요청이 무제한으로 외부 API/파일 저장을 소비하지 않도록 일일 횟수와 별도로 **새 분석 준비 분당 5개, 실행 시작 간격 15초, 동시에 실행 1개, 분석당 실행 최대 2회**를 적용한다. 짧은 요청 제한은 `ANALYSIS_RATE_LIMIT`으로 반환하며 하루 이용 한도와 구분한다. 중복 터치는 동일 분석 ID를 재사용한다. 각 실행 안에서 Gemini 분석 요청이 503으로 실패하면 최대 두 번 자동 재시도하므로, 두 실행 모두 수행할 때 외부 분석 요청은 최대 6회다. 공급자 콘솔에서도 프로젝트 이용량/요금 알림과 할당량을 설정한다. 앱의 성공 건수 제한이 서비스 전체 비용 상한을 보장하지는 않는다.

관리자 테스트 권한은 인증된 사용자의 DB `profiles.role = 'admin'`으로 판정한다. 준비와 실행 양쪽에서 검사하며, 클라이언트가 보낸 role은 사용하지 않는다. 본인의 기존 결과 조회와 일반 상담 접수는 유지한다. 운영 DB에서 사용자가 자신의 role을 바꿀 수 없도록 하는 기존 프로필 권한도 확인해야 한다.

### 4. 서버 함수 배포

연결된 Supabase 프로젝트를 확인한 뒤 실행한다.

```sh
npx supabase functions deploy analyze-as-issue
npx supabase functions deploy cleanup-as-analyses
```

`verify_jwt=false`는 무인증 처리를 의미하지 않는다. 분석 함수는 매 요청마다 `auth.getUser()`로 토큰을 검증하고 계정 상태/소유권을 검사한다. 정리 함수는 별도의 장문 비밀값을 검증한다. 두 함수의 최초 배포는 2026-09-29에 완료했으며, 코드를 바꾸면 해당 함수를 다시 배포해야 한다.

### 5. 보관 기간 작업 등록

Supabase Vault에 `as_ai_project_url`(프로젝트 HTTPS URL), `as_ai_cleanup_secret`(서버 비밀값과 동일)을 등록한 뒤 아래 파일을 SQL Editor에서 실행한다.

`supabase/manual/as_ai_cleanup_schedule.sql`

- 매시간 15분에 실행한다. 이 스케줄을 등록하지 않으면 기간이 지난 데이터가 자동 삭제되지 않는다.
- 분석 전용 사진/영상: 30일 경과 후 정리. 실제 문의 첨부는 기존 문의 저장 정책을 유지한다.
- 문의에 연결하지 않은 분석: 30일 경과 후 정리. 문의에 연결한 결과는 문의와 함께 유지한다.
- 제공사 파일: 분석 후 즉시 삭제 요청한다. 실패/중단 시 기록한 파일명을 정리 작업에서 재시도한다. 제공사 Files API 자체 만료도 별도로 존재한다.
- 물리 파일이 지워지기 전에 DB 기록부터 삭제하지 않는다. 탈퇴 등으로 참조를 잃은 분석 저장소 파일도 검사한다.
- Cron 이력뿐 아니라 `net._http_response`의 HTTP 상태/오류를 확인한다. 실패 응답은 다음 실행에서 재시도되므로 장기 실패를 모니터링해야 한다.

정리용 비밀값은 로컬 터미널에서 `openssl rand -hex 32`로 생성할 수 있다. Edge Function Secrets의 `AS_AI_CLEANUP_SECRET`과 Vault의 `as_ai_cleanup_secret`에 같은 값을 등록한다. Gemini API 키와 다른 값이어야 하며 채팅/소스 코드에 공유하지 않는다.

### 6. 검수 및 앱 확인

관리자 > AI 셀프 가이드에서 적용 범위/준비물/절차/주의/중단 조건을 검토하고 게시한다. 가이드가 없거나 철회된 경우 수리 방법을 표시하지 않는 것이 정상이다.

첨부 없는 질문, AI 생략, 답변/상담 단계 왕복, 질문 수정 후 이전 결과 미연결, 사진 1장/여러 장, 30초 이하 MOV/MP4/WebM, 소리가 있는 영상, 초과 길이, 위험 사진, 흐린 사진, 실패/재시도, 계정 변경과 문의 연결을 실제 기기로 확인한다. Gemini 키가 없으면 '준비 중'으로 처리하며 가짜 결과를 만들지 않는다.

새 네이티브 라이브러리를 추가하지 않았다. iOS/Android 설치 앱의 업데이트는 기존 프로젝트의 배포 절차를 따른다.

## Gemini 연결 오류 확인

### 일반 누수와 위험 확인 질문

`물이 새요` 선택과 일반적인 세면대/수도꼭지 누수 설명만으로 입력 안전 규칙이 발동하지 않는다. 전기 관련 분야/증상 선택이나 실제 천장 누수, 벽 내부 배관 등 위험 설명이 함께 있으면 기존 안전 제한은 유지된다.

AI의 `follow_up_questions`는 관찰된 위험 근거와 분리한다. 예를 들어 `주변 콘센트에 물이 닿았나요?`는 실제로 젖었다는 증거가 아니므로, 이 질문의 키워드만으로 고위험/긴급 상태로 올리지 않는다. 대신 `needs_more_info`, `risk_level=unknown`, `safety_uncertain=true`로 처리하고 셀프 가이드를 제공하지 않는다. 모델의 명시적 `hazards`, 고위험/긴급 분류, 실제 설명/관찰/예상 원인에서 발견한 위험은 여전히 우선한다. 질문에 담긴 분해 지시나 링크도 기존 출력 검증을 통과해야 한다.

공급자 지시문에서도 노출된 수전 문제와 매립 배관/천장/침수/전기 주변 누수를 구분하며, 단순 확인 질문을 위험 발견 사실처럼 기입하지 않도록 안내한다. 실제 모델이 위험으로 분류한 결과를 단순히 물 관련 문의라는 이유로 강제 하향하지는 않는다. 이 수정은 모의 응답 회귀 테스트로 검증하며, 실제 사용자가 받은 이전 모델 응답의 원인까지 확정한 것은 아니다. 이미 저장된 결과는 자동 재분석하거나 덮어쓰지 않는다.

공유 안전 정책과 프롬프트 변경은 `analyze-as-issue` 재배포로 적용한다. 앱 쪽 공유 코드도 배포/개발 Reload 대상이다. 이 변경 자체에는 새 SQL이 없지만, 앞서 추가한 `20260930000000_as_ai_completed_quota.sql`이 아직 미적용이면 먼저 적용해야 한다.

### 오류 코드

`AI 분석은 아직 준비 중`은 서버 활성화/필수 환경변수 확인 단계의 오류다. Gemini 요청 후 실패는 별도 코드로 표시하며, Edge Function 로그에는 단계/HTTP 상태/고정 오류 코드만 기록한다. API 키, 입력 증상, 파일 URL, Google 원본 오류 응답은 로그에 남기지 않는다.

- `GEMINI_ANALYZE_400_KEY_INVALID`, `401_KEY_INVALID`: 서버 키의 유효성/만료 여부 확인.
- `403_KEY_BLOCKED`: AI Studio에서 차단 상태 확인 후 새 키 등록. 이미 외부에 공유한 키는 재사용하지 않는다.
- `403_PERMISSION`: API 키 사용 제한 및 해당 Google 프로젝트의 API 접근 권한 확인.
- `404_MODEL`: 설정한 모델의 접근 가능 여부와 API 경로 확인. 임의로 유료 모델로 변경하지 않는다.
- `400_REQUEST`, `422_REQUEST`: 요청 형식/매개변수 문제. 무료 등급 변경만으로 해결된다고 가정하지 않는다.
- `402_BILLING`, `400_REGION`: 해당 키가 속한 프로젝트의 요금제/지원 조건 확인. 결제 활성화를 자동 수행하지 않는다.
- `429_QUOTA`: 프로젝트 사용 한도 확인. 한도 초과 요청은 자동 재시도하지 않는다.
- `503_UNAVAILABLE`: 제공사 일시 과부하/중단. 분석 및 첨부 상태 조회만 약 1초, 2초 간격(각 0~0.5초 무작위 지연 추가)으로 최대 두 번 재시도한다. 같은 모델/입력/비저장 설정을 사용하며 별도의 분석 기록을 만들지 않는다.
- 그 외 `5xx_UNAVAILABLE`, `NETWORK`: 제공사 오류 또는 서버와 제공사 사이 연결 실패. 처리 여부가 불명확한 네트워크 실패 등은 자동 재전송하지 않는다.

503 응답에 `Retry-After`가 있으면 그 시간 이전에 재시도하지 않는다. 요구 대기가 10초를 넘으면 즉시 오류로 반환하며, 대기 중에도 기존 105초 실행 제한으로 중단된다. 파일 생성/업로드 완료 요청은 중복 파일을 만들지 않도록 자동 재시도하지 않는다. 실패가 이어지면 오류와 기존 상담 전환을 유지하며, 가짜 답변이나 임의 모델/요금제 전환은 하지 않는다. 자동 재시도는 외부 장애 복구를 보장하지 않는다.

같은 분석의 실행 2회를 소진하면 `ANALYSIS_RETRY_LIMIT`, 만료되면 `ANALYSIS_EXPIRED` 코드를 반환한다. 준비 단계에서도 확인해, 사진 재업로드가 먼저 저장소 권한 오류로 실패하지 않도록 한다. 앱의 주 버튼은 `새 분석으로 질문하기`로 바뀌며, 사용자가 눌러야만 새 ID로 시작한다. 증상/첨부/동의는 유지하며 **새 분석을 시작하는 것만으로는 일일 횟수가 차감되지 않는다. 성공 결과가 저장될 때만 차감된다.** 하루 한도, 짧은 요청 제한, 진행 중 요청, 일시적 연결 실패에는 ID를 자동 변경하지 않는다. 기존 서버의 코드 없는 재시도 한도 문구도 지원한다. 이 화면 변경은 앱의 JavaScript 업데이트가 필요하며 서버 재배포만으로 설치된 앱 화면이 바뀌지는 않는다.

앱 이용 횟수와 Gemini 요청 한도/과금은 서로 다르다. [Google의 결제 FAQ](https://ai.google.dev/gemini-api/docs/billing#am-i-charged-for-failed-requests)는 실패한 요청도 요청 할당량에 포함된다고 설명한다. 503 재시도 각각도 별도 요청이므로, 사용자에게 답변이 없더라도 공급자 요청 한도에 도달할 수 있다. RPM/TPM/RPD 중 실제로 초과한 항목은 AI Studio에서 확인한다. 이 변경은 Gemini의 한도를 복구하거나 503 장애를 해결하지 않는다.

사진/영상 전송 실패는 `ANALYZE` 대신 `UPLOAD_START`, `UPLOAD`, `FILE_STATUS` 단계로 표시한다. 분류는 HTTP 상태와 알려진 오류 정보에 근거하며, 실제 실패 원인이 확인되지 않은 상태에서 해결 완료로 취급하지 않는다. 기존 실패 기록은 이전 문구를 유지하므로 새 요청/재시도의 코드를 확인한다.

### 2026-09-30 실서버 점검

- 같은 Supabase 프로젝트의 서버 키로 모델 조회는 200, 단순 Interactions 요청은 200/완료를 확인했다. 비교용 `generateContent` 요청은 503과 과부하 응답으로 실패했다.
- 앱의 `AsGemini.analyze`와 `applyAsSafetyPolicy`를 그대로 실행한 고정 텍스트 샘플은 한 번 503으로 실패한 뒤 후속 점검에서 약 5.5초 만에 정상 분석됐다. `needs_more_info`, 시각 관찰 0개, 수리 절차 없음으로 텍스트 전용 제한도 유지됐다.
- `gemini-3.5-flash-lite` 비교 요청은 결과 검증을 통과하지 못해 운영 모델을 교체하지 않았다. 모델/요금제/일일 분석 한도는 변경하지 않았다.
- 진단은 고객 자료나 DB 접근 없이 수행했다. 만료되는 임시 인증으로 보호한 함수와 해당 인증 설정은 점검마다 삭제했다. 이 결과는 과부하의 영구 해결이나 지속적인 가용성을 보장하지 않는다.

## 비활성화 / 되돌리기

1. 서버의 `AS_AI_ENABLED=false`로 신규 외부 분석을 중단한다. 진행 중 요청은 최대 한 요청의 실행 시간만큼 남을 수 있다.
2. `lib/appMode.ts`의 `SHOW_AS_AI_ANALYSIS=false`로 문의 화면과 결과/분석 내역 진입을 숨긴다.
3. 기존 일반 문의는 AI ID 없이 이전처럼 접수된다. 이미 저장한 분석/문의 연결은 삭제하지 않는다.
4. 기능을 꺼도 보관 기간 정리 작업은 유지한다. SQL 롤백/테이블 삭제는 연결된 문의가 있는지 확인하기 전에는 하지 않는다.
